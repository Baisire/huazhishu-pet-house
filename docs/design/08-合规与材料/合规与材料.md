## 8.1 主体与资质

个人主体做纯 IAA 小游戏，通常需要：开发者实名认证、软著证书、游戏自审自查报告、隐私政策与用户协议、以及平台当期要求的其他材料。**不接受内购**，因此不涉及版号中的"付费"环节，但休闲游戏是否需要版号/备案，各平台在不同时期口径不同，必须以提审时抖音开放平台的《小游戏审核规范》为准，建议在立项阶段就向平台客服书面确认一次并留存截图。

## 8.2 隐私政策要点

必须写清：收集的信息（抖音 openid、设备型号、系统版本、网络类型、广告标识）、收集目的、使用方式、共享对象（广告与统计 SDK）、存储期限、用户权利（查询/删除/注销）、联系方式、更新日期。所有 SDK 在隐私政策中逐一声明，与代码里实际初始化的 SDK 一一对应。

## 8.3 未成年人保护

- 适龄提示：8+；
- 无内购、无充值、无抽奖付费，天然规避未成年人付费风险；
- 防沉迷由平台实名体系承接，客户端不重复实现；
- 广告频次对全部用户统一上限（8 次/日），不因"未成年"标签做差异化投放；
- 不使用"限时""仅剩"等制造焦虑的文案。

## 8.4 广告合规

不得自动播放、不得遮挡核心操作、不得诱导点击、关闭按钮必须可见可点、奖励必须与描述一致、单日频次不得超过配置上限。审核时平台会实际走查广告点位，建议在提审说明中主动列出全部 8 个点位及截图。

## 8.5 软著申请材料

| 材料    | 要求                                                    | 准备时点        |
| ----- | ----------------------------------------------------- | ----------- |
| 申请表   | 名称、版本号、开发完成日期、首次发表日期                                  | M3          |
| 源程序   | 前 30 页 + 后 30 页，每页 ≥50 行，共 60 页；页眉含软件名称与版本号，删除空行与纯注释行 | M3 代码冻结后导出  |
| 说明书   | 含软件名称/版本、运行环境、功能模块说明、操作说明、界面截图；建议 15–25 页             | M2 起写，M3 补图 |
| 权属证明  | 个人身份证正反面                                              | M3          |
| 名称一致性 | 软著名称需与上架名称一致或高度相关，提前在平台查重                             | M1          |

经验提示（非官方口径）：普通通道审查通常需要 1–2 个月，加急通道可缩短到数个工作日；软著证书是提审的硬门槛，建议在代码可运行后立刻提交，不要等美术完成。
