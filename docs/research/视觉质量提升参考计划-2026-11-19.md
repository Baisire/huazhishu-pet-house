## 0. 目标与边界

本计划解决的是“原型能跑，但画面粗糙、像素材拼贴”的问题，不是重做玩法。

核心判断：

1. 视觉粗糙的主因不是 Canvas 代码写得少，而是**资产像素网格、渲染层级、UI 语言、动画方式**没有统一。
2. 优秀商业作品大多闭源，不能也不应该通过反编译或压缩包还原去复制代码。
3. 正确做法是学习公开的通用技术模式，再用开源示例和自有素材复现。
4. 测试版阶段不换引擎、不押注竖屏或正式美术路线，先做一次可对比的视觉 Spike。

## 2. 当前原型的视觉诊断

| 问题 | 当前表现 | 根因 | 优先改法 |
|---|---|---|---|
| 像素网格不统一 | 物件像贴图拼贴，细节有糊有噪 | AI 图按 `1280×720` 生成后压到 `640×360`，不同物件的像素密度不一致 | 关键物件按 1× 重绘；统一色板；背景降低细节和对比；禁止混用不同像素尺度 |
| 深度关系错误 | 鼠鼠永远覆盖在所有物件上，纸箱窝/跑轮无法正确遮挡 | 当前渲染顺序固定为物件 → 鼠鼠 → 前景栅栏；物件没有按落地点排序 | 建立按 `baseY` 排序的渲染队列，鼠鼠和物件在同一队列中绘制 |
| 前景栅栏是整张覆盖层 | 栅栏压住所有下方物体，纵深关系只有一层 | 前景层是一张全屏 PNG | 拆分近景立柱/横杆与可遮挡区域；按深度决定前后关系 |
| UI 不是像素语言 | 文字边缘发虚，面板和场景像两套游戏 | 使用 `Microsoft YaHei` 等抗锯齿系统字体 | 换成中文像素字体；字号只用 8/12/16；坐标和字号取整；图标改为像素资产 |
| 动画依赖位移模拟 | 鼠鼠只会上下浮、翻转，缺少待机/走路/进食的可读动作 | 单张精灵 + bob；没有 sprite sheet 或分层骨骼 | 先做待机 2 帧、走路 4 帧、吃/喝各 2 帧；再补尾巴/耳朵二次运动 |
| 光效不是像素语言 | 暗角和暖光是平滑 Canvas 渐变 | 径向渐变和半透明椭圆是抗锯齿图形 | 低分辨率 Bayer 抖动、像素化阴影、少量木屑/灰尘粒子 |
| 构图比例失衡 | 栅栏占比过高，房间偏浅 | 背景和前景没有按目标画面重新构图 | 栅栏控制在画面高度 15%–18%；鼠鼠和主要玩具保持视觉中心 |

已具备的基础：固定 `640×360` 虚拟分辨率、CSS `image-rendering: pixelated`、绘制时关闭平滑、场景分层结构、物件状态图切换。这些可以保留，不需要推倒重来。

## 3. 视觉规则

### 3.1 像素网格与缩放

- 所有游戏内坐标使用虚拟像素，绘制前取整。
- 角色移动可以保留浮点逻辑坐标，但 `drawImage`、阴影、粒子、文字必须落到整数坐标。
- 以 `640×360` 为验收分辨率；预览截图固定输出 `1280×720`，避免浏览器窗口比例影响判断。
- 关键资产按 1× 像素网格绘制，导出后不再用平滑缩放。
- 背景可以使用较少的细节和较大的色块，但不能出现细密的抗锯齿纹理。
- 像素风 QA 时检查：是否出现非整数宽高、半像素位移、模糊边缘、不同物件像素点大小不一致。

### 3.2 深度与遮挡

- 场景节点至少包含 `baseY`、`draw` 和可选的 `occluder`。
- 每帧把物件、鼠鼠、前景遮挡物放进同一渲染队列，按 `baseY` 从远到近绘制。
- 互动站位不只是 `standX`，还要能指定 `standY` 或靠近物件的深度偏移。
- 前景栅栏拆成“近景立柱/横杆”和“可穿过区域”，不要用一张全屏 PNG 无条件覆盖。
- 鼠鼠走到物件后方时，必须能被物件或前景遮挡；走到前方时，必须压住物件底部。

### 3.3 资产管线

- 先定 24–32 色暖色板，再开始重绘。
- 关键物件：跑轮、水瓶、食盆、纸箱窝、球、鼠鼠本体，按同一像素尺度重绘。
- 背景优先做“低细节、低饱和、明确明暗分区”，不要保留 AI 图的高频笔触。
- 透明底物件导出前检查边缘：不能有黑边、白边、半透明灰边。
- 物件状态至少两态：
  - 水瓶：有水 / 低水位
  - 食盆：有粮 / 空盆
  - 跑轮：静止 / 转动
  - 纸箱窝：空 / 鼠鼠进入
- 所有资产记录来源和许可，不把参考作品的素材直接用于项目。

### 3.4 UI

- 中文像素字体优先使用 Fusion Pixel 12px；字号限定 8/12/16。
- 面板使用直角、2px 描边、硬阴影，不使用圆角和半透明系统风面板。
- 数值条、瓜子、等级、动作按钮全部使用同一套像素图标。
- 文本位置取整；不要用 `12.5px`、`1.5` 透明度这类半像素值。
- HUD 可以保留现有信息结构，但视觉语言必须和场景一致。

### 3.5 动画

- 第一批只做四个状态：待机、走路、吃、喝。
- 推荐帧数：待机 2 帧循环，走路 4 帧循环，吃/喝各 2 帧。
- 所有帧共用脚底锚点，避免切换时角色上下跳动。
- 二次运动优先级：尾巴摆动 > 耳朵抖动 > 眨眼 > 呼吸起伏。
- 没有完整帧之前，位移和起伏只能作为临时表现，不能作为最终动画方案。

### 3.6 光照与后期

- 禁止大面积平滑径向渐变。
- 暗角、暖光、地面接触阴影使用低分辨率绘制再放大，或用 Bayer 抖动。
- 物件底部必须有接触阴影；阴影不追求写实，追求把物件“压”在木屑上。
- 光照方向统一为左上，和场景资产保持一致。
- 粒子限制在木屑、灰尘、星星、爱心四类，尺寸和颜色服从色板。

### 3.7 构图

- 目标构图：墙 25%–30%，木屑地面 40%–45%，栅栏 15%–18%，草地 8%–10%。
- 鼠鼠放在画面中偏右或中偏左，避免和 HUD 重叠。
- 跑轮、纸箱窝、水瓶形成三个视觉锚点；食盆和球做次级互动。
- 互动热区必须和可见轮廓一致，避免点到大量透明区域。
- 每个可互动物件都要有“未互动 / 互动中 / 已变化”三种视觉状态中的至少两种。

## 4. 技术学习路线

### 4.1 学什么，不学什么

不通过反编译、扒压缩包或复制闭源项目代码来学习。只学通用模式：

- 像素完美相机与整数缩放
- 2D 深度排序与 `baseY` 锚点
- TileMap、精灵图集、锚点和九宫格 UI
- 低分辨率渲染纹理、调色板量化和抖动
- 精灵动画事件、状态机和二次运动

### 4.2 开源参考

| 参考 | 用途 |
|---|---|
| [Phaser Examples](https://github.com/phaserjs/examples) | 像素相机、精灵、深度排序、输入和场景组织 |
| [PixiJS Examples](https://pixijs.com/examples) | 渲染纹理、滤镜、分层、性能组织 |
| [Godot Demo Projects](https://github.com/godotengine/godot-demo-projects) | 2D 像素完美、YSort、TileMap、角色状态机 |
| [Fusion Pixel Font](https://github.com/TakWolf/fusion-pixel-font) | 中文像素字体候选 |
| [LibreSprite](https://github.com/LibreSprite/LibreSprite) | 精灵图和逐帧动画制作 |
| [Lospec Palette List](https://lospec.com/palette-list) | 暖色像素色板参考 |

学习方法是“每次只复现一个技术点”：

1. 在开源示例中找到对应实现。
2. 用 30–80 行代码在我们自己的 Canvas 渲染层做一个 spike。
3. 用固定截图对比前后效果。
4. 确认有效后再合并，不整包搬架构。

## 6. 验收清单

- [ ] 固定使用 `640×360` 虚拟分辨率，预览截图输出 `1280×720`。
- [ ] 游戏层颜色数量控制在 32 色左右，没有大面积平滑渐变。
- [ ] 精灵、阴影、粒子和文字都落在整数像素坐标。
- [ ] 鼠鼠和物件按 `baseY` 排序，存在真实前后遮挡。
- [ ] 鼠鼠走到纸箱窝/跑轮后方时会被正确遮挡。
- [ ] 前景栅栏不超过画面高度 18%。
- [ ] HUD 不使用系统抗锯齿字体，不使用圆角半透明面板。
- [ ] 待机、走路、吃、喝四个动作可区分。
- [ ] 水瓶、食盆、跑轮至少各有两种状态。
- [ ] 跑轮、水瓶、食盆、纸箱窝、球都有接触阴影。
- [ ] 点击热区和可见轮廓基本一致。
- [ ] 截图检查没有黑边、白边、灰边和缩放糊边。

## 7. 第一轮代码 Spike 范围

只做视觉，不改数值和玩法：

1. 新增像素绘制工具：坐标取整、像素阴影、抖动矩形。
2. 改造场景渲染队列：物件、鼠鼠、前景遮挡物按 `baseY` 排序。
3. 拆分前景栅栏，先支持纸箱窝和跑轮的前后遮挡。
4. HUD 换像素字体和像素图标，布局保持现有交互不变。
5. 统一色板和光照方向，先做一张对比截图。
6. 用一张鼠鼠待机/走路 sprite sheet 验证动画管线。

Spike 完成标准：同一场景在修改前后各截一张图，能明确看出“拼贴感”下降，而玩法和点击位置没有变化。

## 8. 风险与非目标

- 不在本轮决定竖屏/横屏、Cocos/PixiJS 或正式美术路线；第 10 章决策状态保持不变。
- 不重写数值层、存档层、探险逻辑和广告逻辑。
- 不增加多货币、店员、菜谱、任务链等系统。
- 不直接使用参考作品的代码、素材、角色设计或受版权保护的 UI。
- 如果资产本身仍由高分辨率 AI 图压缩而来，只靠代码无法彻底消除拼贴感；关键资产必须重绘或做严格的像素化重制。
