## 0. 项目定义与前置判断

### 0.1 一句话定义

一款竖屏、单指操作、可离线挂机的花枝鼠（宠物鼠）养成小游戏：每天回小屋照料鼠鼠、收拾房间，派它出门探险，把带回来的战利品摆进屋里，慢慢把小屋养成"鼠鼠的家"。

### 0.2 目标用户与场景

- 核心人群：18–35 岁、有宠物内容消费习惯的轻度用户，女性占比预计 60%–70%（经验判断，非官方数据）。
- 使用场景：通勤、睡前、工作间隙的 3 分钟碎片时间；夜间 21:00–24:00 为高峰（经验判断）。
- 竞品心智参照：旅行青蛙提供的是"等待 + 明信片"的情绪价值，但玩法极薄、复访被动。本作不复制"等待—收明信片"的单一结构，而是把重心放在**小屋的可见变化**（家具摆放、房间扩建、鼠鼠行为）与**短周期探险收益**上，形成"照料—派遣—布置"的主动循环。

### 0.3 设计原则（冲突时的裁决顺序）

1. **不惩罚**：任何数值归零都不导致死亡、掉级、物品丢失。所有失败只体现为"这次收获少"。
2. **不打断**：不存在操作过程中弹出的广告，所有广告由用户主动点击触发。
3. **三十秒有反馈，三分钟有进展**：任何一次进入游戏，30 秒内必须看到可见变化（鼠鼠动作/数值回升/探险结算）。
4. **竖屏单指**：全部交互在拇指热区完成，不做需要双手或多点的手势。
5. **配置驱动**：数值、价格、文案、活动、广告点位全部走 JSON，改数值不发版。
6. **双端同源**：业务逻辑不直接调用平台 API，全部经适配层，H5 端可完整跑通（含模拟广告）。

### 0.4 原型资产盘点与遗留问题处置

原型已具备：Canvas 2D 手绘、600×450 逻辑分辨率、32×32 字符网格像素鼠（8 动作 / 3 配色）、木纹墙 + 木屑地板 + 窗户 + 5 件家具、四项数值实时衰减、9 个按钮、localStorage 存档。这套东西可以整体迁移为**逻辑规则原型**，渲染层重写。

| # | 问题           | 根因判断                    | 处置方案                                     | 归属阶段 |
| - | ------------ | ----------------------- | ---------------------------------------- | ---- |
| 1 | 调试色条残留       | 调试层与 UI 层未分离，overlay 常驻 | 调试绘制独立开关，仅 dev 构建注入；生产包编译期剔除             | M0   |
| 2 | 启动自检闪屏       | 资源自检同步执行并逐帧重绘           | 改为异步预检 + 启动遮罩淡入，自检结果只写日志不重绘              | M0   |
| 3 | 尾巴方向画反       | 角色朝右时尾巴锚点未做镜像           | 统一"角色始终朝右，向左时整体 scaleX=-1"，尾巴锚点写在角色局部坐标系 | M0   |
| 4 | 耳朵与头脱节       | 耳朵偏移写死在世界坐标             | 耳朵作为头部子节点挂载，跟随头部缩放/位移                    | M0   |
| 5 | 数值衰减过快且归零无后果 | 按帧衰减、无离线折算、无状态后果        | 改为按小时衰减 + 离线系数 + 状态分影响收益（见 2.1）          | M0   |
| 6 | 自动存档覆盖手动存档   | 单槽 localStorage         | 多槽 + 版本号 + 备份槽 + 迁移链（见 4.4）              | M1   |
| 7 | 家具只能拖不能增删    | 场景对象即数据源                | 拆为 `inventory`（未摆放）与 `placed`（已摆放）两张表    | M1   |
| 8 | 称号只有 6 个     | 硬编码                     | 扩到 20 个，写入配置 `level.titles`              | M2   |
| 9 | 600×450 横屏   | 原型分辨率设定                 | 改为竖屏 750×1334 设计分辨率（见 10.1）              | M1   |

## 9. 生产计划

### 9.1 里程碑

| 阶段       | 目标                  | 交付物                                 | 验收标准                     |
| -------- | ------------------- | ----------------------------------- | ------------------------ |
| M0 原型体检  | 修正原型 9 项遗留问题，确定数值基线 | 修复后的原型、数值试算表                        | 连续 3 天模拟游玩，四项数值不出现"半天全空" |
| M1 技术底座  | 引擎跑通抖音 + H5 双端      | 空场景双端可运行、广告/存档/分享接口打通               | 真机（安卓 + iOS 抖音）各跑通一次完整流程 |
| M2 核心循环  | 陪伴 + 探险 + 收集的最小闭环   | 可玩垂直切片（1 房间 / 6 家具 / 2 探险档位）        | 3 名未接触过的用户能在无提示下完成一次完整循环 |
| M3 内容量产  | 美术替换 + 内容补齐         | 30 家具 / 8 皮肤 / 40 照片 / 20 称号 / 3 扩建 | 全资产进包，主包 ≤3MB            |
| M4 变现与留存 | 8 个广告点位 + 签到任务活动    | 联调完成的商业化版本                          | 广告点位全部可用，频控准确，无打断        |
| M5 合规提审  | 材料齐备并提交             | 软著证书、隐私政策、自审报告、提审包                  | 审核通过                     |
| M6 上线迭代  | 数据驱动调优              | 数据看板、周更内容节奏                         | VA/DAU 与次留达到 7.3 的目标线    |

### 9.2 并行关系

| 工作项         | 可并行的阶段   | 说明                  |
| ----------- | -------- | ------------------- |
| 软著说明书撰写     | M2 起     | 功能截图可在垂直切片阶段先截，后面替换 |

## 附：术语与约定

| 术语     | 含义                      |
| ------ | ----------------------- |
| 状态分    | 四项数值加权平均，0–100，仅内部使用    |
| VA/DAU | 人均日有效激励视频观看次数           |
| 自然产出   | 不看任何广告情况下的日均瓜子收入        |
| IAA    | In-App Advertising，广告变现 |
| 空手而归   | 探险收益为 0 的结算状态，不涉及资产损失   |

***

*本文档中标注"经验判断"的数值均为基于同类休闲小游戏的一般观察，非官方统计口径，上线后应以自有数据校准。*
